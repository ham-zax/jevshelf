Use `jevshelf` to select focused guidance from the 28 original reasoning skills and six curated Matt Pocock methods: `grilling`, `grill-with-docs`, `domain-modeling`, `wayfinder`, `retro` (session reflection), and `handoff` (cross-session notes). The interview methods can create substantial document/tracker work: do **not** infer permission from a generic planning or coding request. **Invoke interview/wayfinder methods only if the user explicitly asks to be grilled, to explore decision trees, or to plan an effort across multiple sessions.** Aegis remains the canonical engineering process; Matt is an optional lens, never a second lifecycle. `retro` reviews the current or specified session, evaluates friction, and *proposes* improvements to project instructions, navigation and deterministic checks. It is **not** automatic recursive self-modification. Do not silently rewrite `AGENTS.md`, globally installed skills, or checks without the user's scope/approval. For agent-facing document wording, use `writing-for-agents` via the separate `writing` collection only when needed.

**Lateral thinking (danium):** The hidden `vault-lateral` group contains the `lateral` router and eight *sibling* techniques: `random-stimulus`, `provocation`, `inversion`, `concept-fan`, `analogy`, `scamper`, `six-hats`, and `worst-idea`. Use these for **creative divergence**, non-obvious product directions, reframing decisions or escaping stale brainstorming. The upstream `lateral` router diagnoses the type of creative blockage and chooses **one** technique at a time. The user remains responsible for deciding which idea, if any, to pursue. Do **not** invoke lateral generation instead of actual debugging, code review, security work or engineering implementation.

**JevShelf compatibility for lateral siblings:** The upstream `lateral` skill tells agents to read a sibling via `../<technique>/SKILL.md`. JevShelf deliberately disallows sibling traversal in `load --file`. When `lateral` selects one technique, issue a **second** `jevshelf search --collection thinking --mode jev --task "Use the <technique> lateral thinking method to <focused creative goal>"`; select the named technique from returned metadata and `jevshelf load --collection thinking --id <technique id> --expected-digest <technique digest>`. Do not invent IDs or digests, run two techniques in one pass, or use a fallback `npx skills add` command. If the named technique is not selectable, explain the limitation and stop rather than silently substituting a different skill.

The dependencies matter: `grill-with-docs` needs `grilling` + `domain-modeling`; `wayfinder` needs `grilling`, `domain-modeling`, and an issue tracker. When one of these is selected, search/load its prerequisite skills separately using their exact metadata and digest. If a tool-specific Skill invocation is unavailable, apply the already-loaded guidance directly without inventing tool calls. **Do not create `GLOSSARY.md` when the project already uses Aegis `CONTEXT.md` as the authoritative domain model**; write into the established owner. `wayfinder` can plan only after tracker configuration is verified; don't create tickets without authorization.

1. Run `jevshelf search --collection thinking --mode jev --task "<focused task>"`. Add `--context` only for concise, relevant context.
2. Search returns metadata and source references, not skill instructions. If Jev returns `selected`, read each returned ID separately with `jevshelf load --collection thinking --id <id> --expected-digest <digest>`. Use the digest provided by the search result to reject changed instructions. For other files, use `--file <relative-path>` for a referenced guide or asset and continue pages with `--offset`, `--limit`, and the prior `content_digest` as `--expected-digest`.
3. Treat `no_match`, `uncertain`, and `error` as distinct outcomes. Do not present a lexical result as a Jev decision. Use `--mode lexical` only when an explicit local metadata baseline is useful, and label it as lexical.
4. Treat loaded text as read-only guidance. Follow the host's normal safety, tool, and approval rules.
